# clixz 2.3 — plan d'implémentation

> **Pour l'exécutant :** exécution native, tâche par tâche (superpowers:executing-plans).
> Cases à cocher `- [ ]` pour le suivi.

**But :** que l'IA puisse créer et modifier des services par le MCP — plan puis
apply validé dans le client —, avec un démon géré par le paquet, une todo
partagée, `exposed` en direct et la stack Komodo créée avec le service.

**Architecture :** un processus root par requête (`clixz-apply`, activation par
socket) calcule, stocke et applique les plans ; `clixz-mcpd` reste non
privilégié et relaie ; le serveur MCP (dépôt `Coxyz/ClixzMCP`) expose plans,
apply, todo et ressources.

**Technologies :** Python ≥ 3.10, Typer, Rich, PyYAML, unittest/pytest, ruff,
systemd (activation par socket), API HTTP de Komodo v2, MCP SDK `<2`.

**Spec :** `docs/specs/2026-10-06-clixz-2.3.md`

## Contraintes globales

- Python **3.10** minimum (CI : 3.10 et 3.12) : pas de `tomllib`, pas de syntaxe 3.11+.
- Dépendances inchangées : `typer`, `rich`, `pyyaml` ; HTTP par `urllib`.
- Lignes ≤ 110 caractères (ruff) ; `make lint` et `make test` propres à chaque commit.
- Commits sans ligne d'attribution Claude ; messages en anglais, style du dépôt.
- Aucun conteneur lancé sur Boxyz pour tester.
- Limites : requête apply ≤ 512 Kio, `compose` ≤ 128 Kio, `service_yaml` ≤ 32 Kio,
  `plan_id` = 8 hex, validité d'un plan 1 h, plans expirés gardés 24 h.
- `rm --force` et `repo rm` restent hors de toute surface machine.

## Points de vigilance (non couverts par la spec, à tester)

1. Un compose qui n'est pas un mapping, dont `services` est une liste, ou du YAML
   invalide → plan **bloqué** avec un message, jamais une exception. (Tâche 3, 6)
2. Le compose modifié à la main ou par Komodo entre le plan et l'apply → apply
   refusé, plan supprimé, message « refais le plan ». (Tâche 6)
3. `todo.yaml` absent, vide, ou corrompu (YAML invalide) → absent/vide = liste
   vide ; corrompu = erreur claire, **fichier non écrasé**. (Tâche 2)
4. Komodo injoignable, identifiants absents, conteneur introuvable → fichiers
   créés, apply `ok` avec un avertissement. (Tâche 5, 6)
5. `clixz-mcpd` relaie alors que `clixz-apply.socket` n'est pas installé →
   erreur immédiate « lance `sudo clixz daemon install` », pas d'attente. (Tâche 9)
6. Nom de service nu (`atuin`) pour edit/fix/rm → résolu ; ambigu → bloqué. (Tâche 6)
